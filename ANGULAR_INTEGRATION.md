## Implementation
1. Retain the existing Angular homepage component and its `addHomeSchema()` logic, current language subscription and routing. Move only the approved Vision homepage sections into the home component; integrate the redesigned footer separately through the existing shared footer/disclaimer components. Do not copy the prototype document `<head>`, nav, `noindex` tag or global styles.
2. Scope design CSS under a unique homepage host/wrapper. Reuse the project font and brand tokens. Split or simplify the long standalone stylesheet as needed; Angular's `anyComponentStyle` maximum error budget is 30 kB in `angular.json`, so do not paste the entire 98 kB standalone CSS into a single component stylesheet. Remove unused prototype-only styles. Prefer isolated component styles for markets, globe, accounts, platform, and reviews.
3. Use typed component state for market categories/time periods, OHLC candle arrays and review selection rather than copying global DOM scripting. Bind real router links and existing product descriptions. Use the existing live trading widget/data provider; replace the illustrative chart or clearly retain its demo label. Do not generate fake prices or client reviews.
4. Initialize canvas, IntersectionObserver, requestAnimationFrame, and timers only in the browser (e.g. `isPlatformBrowser` guard and `ngAfterViewInit`). Dispose observers, timers, animation frames and listeners in `ngOnDestroy`. Keep meaningful HTML visible without animation for SSR/crawlers. Respect prefers-reduced-motion.
5. Reuse translation keys via the existing `localize`, `hybridTranslate`, and native i18n catalogs. New copy requires all published language catalogs to be updated and revalidated. Preserve canonical/hreflang, language-specific HTML, RTL, schema, robots and sitemap behaviour. Do not mark languages complete without real reviewed translations.
6. Verify the existing account details, registration and demo flows, MT5 download links, all 6 market routes, partnership routes, legal documents, analytics consent and existing Trustpilot content. Use client-approved text and current trading-risk disclosure. Keep legal and footer content intact.
7. Run the repository's install, normal production build and SSR build/test scripts. Test source HTML before JS, language switch, partnership navigation, all breakpoints (including 360 px), keyboard controls and reduced motion. Benchmark real Core Web Vitals on a staging deployment. The standalone preview does not certify these production checks.
8. Commit only approved changes to the feature branch. Review diff and staging build, then follow your existing GitHub → Jenkins deployment process. No new AWS uploads or changes to Jenkins are needed just to evaluate this prototype.
